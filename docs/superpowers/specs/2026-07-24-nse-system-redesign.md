# NSE Stock Prediction System — Audit & Redesign Spec

**Date:** 2026-07-24  
**Status:** Approved  
**Scope:** Historical price database (RTDB), daily price update, company news, financial statement interpretation, deep price analysis, HTML report removal

---

## 1. Context & Audit Findings

### What Currently Works
- React/TypeScript frontend (Vite, deployed to Cloudflare Pages)
- Daily ML pipeline: price scraping → XGB/ARIMA retraining → ensemble inference → Firestore snapshots
- Intraday price capture (5x daily via GitHub Actions)
- NSE announcement scraping → Firestore `news/{ticker}/items`
- Investor panels: CompanyProfileCard, QuoteSummaryPanel, ValuationPanel, NewsPanel
- Technical indicators in Firestore (RSI, MACD, Bollinger Bands, SMAs)
- CI/CD: 10 GitHub Actions workflows

### What Must Change
- **HTML reports removed:** `reports/outputs/*.html` (5.9MB each, generated by `main.py`) are the current analysis interface. Replaced by the React frontend reading from Firebase.
- **Price data migrated to RTDB:** 46+ tickers with OHLCV history from 2008–2015 onwards live in local CSVs (`data/raw/`, `data/cleaned/`, `pipeline/data/`). These move to Firebase Realtime Database as the authoritative source.
- **No hardcoded prices:** All OHLCV and volume data must be stored in Firebase, never in source code or local-only files.
- **Pipeline scripts retired:** `run_all.py`, `run_pipeline.py`, `pipeline/src/visualization/dashboard.py` are removed. All orchestration runs through GitHub Actions.

### Prices Found Outside Firebase (to migrate)
| Path | Tickers | Schema |
|---|---|---|
| `data/raw/*.csv` | 46+ | Date, Open, High, Low, Close, Volume, Ticker |
| `data/cleaned/*.csv` | 46+ | + Is_Stale |
| `data/features/*.csv` | 46+ | + 45 technical indicators |
| `pipeline/data/raw/`, `cleaned/`, `features/` | Mirror of above | Same schemas |

## 3. Firebase Realtime Database Schema

### Price Node Structure

```
/prices/{ticker}/{YYYY-MM-DD}/
  o    float   Open price (KES)
  h    float   High price (KES)
  l    float   Low price (KES)
  c    float   Close price (KES)
  v    float   Volume traded (shares)
  pc   float   Previous close (KES)
  ch   float   Price change (KES)
  pch  float   Percentage change (%)
  vv   float   Value traded (KES)
```

**Key decisions:**
- Ticker uses short form: `SCOM` not `SCOM.NR`
- Date key is `YYYY-MM-DD` — RTDB orders children lexicographically so date-range queries work natively via `orderByKey().startAt().endAt()`
- Records are **immutable** — pipeline uses `update()` not `set()`, existing date nodes are never overwritten
- CSVs remain on disk as ML training cache (local disk access is faster than RTDB reads for 45-feature matrix generation); RTDB is the API and analysis layer

## 4. Feature 1 — Historical Price Database

### Purpose
Establish Firebase RTDB as the single source of truth for all historical OHLCV data.

### Implementation

**New script:** `pipeline/scripts/migrate_prices_to_rtdb.py`

Steps:
1. Iterate over all tickers in `data/cleaned/`
2. For each row in the cleaned CSV, build the RTDB node
3. Write in batches of 500 records using `db.reference('prices').update(batch)` — `update()` is used so no existing node is overwritten
4. Log progress per ticker; on failure, record the last successful date and resume from there on re-run
5. Skip tickers with fewer than 30 data points

**New script:** `pipeline/scripts/write_prices_rtdb.py`

Called by the daily workflow after each scrape. Writes a single new date node per ticker. Checks if the node already exists before writing (idempotent).

### CI Workflow: `migrate_prices.yml`
- Trigger: manual (`workflow_dispatch`)
- Runs once — a one-time migration
- Uses `FIREBASE_RTDB_URL` + `FIREBASE_SERVICE_ACCOUNT_JSON` secrets
- Estimated runtime: ~15 minutes for 46 tickers × ~2000 days

### Verification
- After migration: RTDB node count matches sum of rows across all cleaned CSVs
- Spot-check 3 tickers (SCOM, KCB, BAT) — compare RTDB values against CSV source

## 5. Feature 2 — Daily Price Update

### Purpose
After market close, scrape the official NSE Daily PDF and write every listed company's OHLCV + corporate actions to Firebase. No company is skipped.

### Implementation

**New script:** `pipeline/scripts/scrape_nse_pdf.py`

Steps:
1. Download PDF: `https://www.nse.co.ke/wp-content/uploads/{DD-MON-YY}.pdf` (e.g., `24-JUL-26.pdf`)
2. Parse all price tables with `pdfplumber` — extract every row
3. For each company row:
   - Fields: ticker, open, high, low, close, previous close, change, % change, volume, value traded
   - Write to RTDB: `prices/{ticker}/{today}` — skip if node already exists
   - Companies with zero volume: write record with `v: 0` (not skipped)
4. Parse corporate actions table from same PDF (dividends, splits, bonus issues, rights)
5. Write corporate actions to Firestore: `companies/{ticker}/corporate_actions/{YYYY-MM-DD}`

**Ticker mapping:** A static lookup table maps PDF company names to short ticker keys. Unknown names are logged as warnings and written with their raw name — not silently dropped.

### CI Workflow: `daily_update.yml` (updated)
- Trigger: `16:30 EAT Mon–Fri` (13:30 UTC — 90 minutes after NSE market close at 15:00 EAT, allowing time for the official PDF to be published)
- Step order: F2 (PDF scrape + RTDB write) → ML inference → F3 (news) → F5 (deep analysis)
- Each step uses `continue-on-error: false` except F3 and F5 (news/analysis failures must not block price data)

### Verification
- Every company in the PDF appears in RTDB with today's date key
- Corporate actions written to Firestore match the PDF's corporate actions table

## 6. Feature 3 — Company News

### Purpose
Collect news from official company IR pages and MarketScreener. Maintain historical news where available (2010 onwards). Existing NSE announcement scraper is extended, not replaced.

### Implementation

**Updated script:** `pipeline/scripts/scrape_news.py` (extends existing)

**Sources added:**
- Official company IR/news pages — 40+ URLs pre-configured per ticker
- MarketScreener news pages — `https://www.marketscreener.com/quote/stock/{ticker}/news/`

**Deduplication:** Existing `doc_id = hash(date + title)` approach preserved. `update()` on Firestore — no overwrites.

**Firestore target:** `news/{ticker}/items/{doc_id}`

```json
{
  "title": "BAT Kenya HY26 Results",
  "date": "2026-07-23",
  "source": "bat.co.ke",
  "summary": "...",
  "url": "https://...",
  "category": "earnings",
  "is_pdf": false,
  "pdf_url": null
}
```

For PDF announcements: `is_pdf: true`, `pdf_url` populated, `summary: null` — frontend renders a download link.

**Historical backfill:** One-time run (`--backfill` flag) crawls MarketScreener news archives back to 2010 per ticker. Daily runs fetch only new items.

### Verification
- At least one news item per major ticker (SCOM, KCB, EQTY, BAT, EABL) within last 30 days
- No duplicate `doc_id`s in Firestore

**Script 3: `pipeline/scripts/analyze_financials_ai.py`**
- Reads extracted metrics from Firestore
- Sends to Claude API (`claude-sonnet-4-6`)
- System prompt: "You are a Kenyan equity analyst writing for retail investors."
- Requested output fields:
  - `summary` — 3-sentence overview
  - `revenue_trend` — direction and driver
  - `profit_trend` — margins and trajectory
  - `debt_levels` — risk assessment
  - `cash_flow_health` — sustainability assessment
  - `dividend_history` — coverage and sustainability
  - `key_risks` — list of 3 risks
  - `growth_opportunities` — list of 2 opportunities
- Stores result in Firestore: `financials/{ticker}/analysis/{period}`

### Firestore Layout
```
financials/{ticker}/
  reports/{period}        ← PDF download manifest
  periods/{period}        ← raw extracted metrics (full schema above)
  analysis/{period}       ← Claude-generated narrative
```

Period keys: `H1-2026`, `H2-2025`, `FY-2025`, `FY-2024`, etc.

### CI Workflow: `analyze_financials.yml`
- Trigger: manual + monthly schedule (1st of each month)
- Runs all 3 scripts in sequence: scrape → extract → AI analysis
- `ANTHROPIC_API_KEY` required in repository secrets
- Skips tickers where current period already has a `periods/{period}` document (idempotent)

## 8. Feature 5 — Deep Price Analysis (Rebuild)

### Purpose
Explain why a stock's price moved, combining all available signals. Currently broken — rebuilt from scratch.

### Implementation

**New script:** `pipeline/scripts/deep_price_analysis.py`

**Inputs gathered per analysis:**
- Last 90 days OHLCV from RTDB `/prices/{ticker}`
- Technical signals from Firestore `companies/{ticker}/technicals/{date}`
- Recent news (last 30 days) from Firestore `news/{ticker}/items`
- Corporate actions from Firestore `companies/{ticker}/corporate_actions`
- Latest financial analysis from Firestore `financials/{ticker}/analysis`

**Claude API call:**
- Model: `claude-sonnet-4-6`
- Input: structured JSON of all inputs above
- Output schema:
  ```json
  {
    "price_movement_explanation": "string",
    "driver_type": "fundamental | sentiment | technical | corporate_action",
    "key_events": [
      { "date": "YYYY-MM-DD", "event": "string", "estimated_impact": "+X%" }
    ],
    "outlook": {
      "short_term": "string",
      "medium_term": "string"
    },
    "confidence": 3
  }
  ```
- Stored in Firestore: `deep_analysis/{ticker}/{YYYY-MM-DD}`

**Trigger:** Nightly, as last step of `daily_update.yml`, after F2 (prices) and F3 (news) complete.
